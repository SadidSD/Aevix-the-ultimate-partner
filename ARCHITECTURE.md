# Jarvis Agent (AEVIX) Architecture

Jarvis (internally referred to as **AEVIX**) is a sophisticated personal productivity assistant built on a modular "Agentic" architecture. It combines real-time activity tracking, LLM-powered insights, and automated scheduling into a cohesive system.

## 🏗️ System Overview

The system is divided into three primary layers:
1.  **Data Layer (Telemetry & Persistence)**: Captures user activity and maintains persistent state.
2.  **Logic Layer (LangGraph Agent)**: Process intents, manages tasks, and generates responses.
3.  **Interface Layer (Web UI & OS Integration)**: Provides user interaction and proactive alerts.

## 🧩 Architectural Components

### 1. The Agent Engine (`agent.js`)
The heart of Jarvis is a **LangGraph** state machine. It uses a directed graph to manage the flow of data and logic.

*   **State (`AevixState`)**: A persistent object storing:
    *   `messages`: Conversation history.
    *   `tasks`: A list of pending/completed tasks.
    *   `activity_summary`: Aggregated data from ActivityWatch.
    *   `energy_prediction`: Predicted user energy levels.
    *   `daily_plan`: The current time-blocked schedule.
*   **Nodes**:
    *   `activity_query`: Fetches raw telemetry from the local ActivityWatch server.
    *   `task_extractor`: Uses a fast LLM (8B) to identify when the user wants to add or complete tasks.
    *   `chat`: The primary interaction node using a high-capacity LLM (70B) to respond in the "Refined Butler" persona.
    *   `analyzer` & `planner`: Specialized nodes for complex nightly processing.

### 2. The Backend Server (`index.js`)
An Express server that bridges the Agent with the outside world.

*   **API Gateway**: Exposes endpoints for the Web UI (Chat, Tasks, Analytics).
*   **Cron Scheduler**:
    *   **Nightly Routine (2:00 AM)**: Runs the `analyzer` and `planner` nodes to summarize the day and prep for tomorrow.
    *   **Reminder Loop (Every 1m)**: Polls the agent state to see if any tasks are approaching deadlines, triggering OS and UI notifications.
*   **SSE Stream**: Provides a real-time "heartbeat" from the server to the browser for proactive alerts.

### 3. Telemetry & Analytics (`analytics.js` & `aw_client.js`)
Jarvis is "context-aware" thanks to its integration with ActivityWatch.

*   **Activity Breakdown**: Aggregates usage data into "Productive" vs "Distracting" categories based on customizable maps.
*   **Insight Generation**: Feeds aggregated data back into the LLM to provide weekly/daily productivity reports and actionable recommendations.

### 4. Persistence Layer
Uses `SqliteSaver` (LangGraph checkpointer) to ensure that the agent's memory, task list, and long-term state survive application restarts.

## 🔄 Core Workflows

### Standard Conversational Flow
1.  **User Message** → `index.js` (/api/chat).
2.  **`activity_query` Node** → Pulls latest 24h usage.
3.  **`task_extractor` Node** → Identifies any task changes.
4.  **`chat` Node** → Generates persona-driven response using updated state + activity context.
5.  **Response** → Sent back to UI; State saved to SQLite.

### Background "Butler" Routines
*   **Proactive Reminders**: The minute-by-minute cron job uses an LLM to compare $CURRENT\_TIME with task deadlines. If a match is found, it sends a notification.
*   **Nightly Review**: The system self-reflects at 2 AM, predicting tomorrow's energy levels based on today's screen time and habits.
